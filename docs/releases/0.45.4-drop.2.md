# Crew for Drop 0.45.4-drop.2

The guest lowers S3 request costs and bounds restore size, and planned suspend and terminate confirm replication before they answer.

- **Sync interval.** Litestream uploads every 10 seconds instead of every second. Set `DROP_REPLICA_SYNC_INTERVAL` (a Go duration from 1s to 300s) to change it per app. An invalid value is logged and replaced by the default; the guest still starts. With the default, up to about 10 seconds of acknowledged writes can be lost on sudden host loss.
- **Confirmed lifecycle sync.** Suspend and terminate drain requests, stop the Crew process including its background jobs, run `litestream sync -wait` through the local control socket, require the replica position to reach the local position and flush the guest filesystem before answering 200. Otherwise they answer 503 within the hook deadline with `replication: unconfirmed` and the failed stage. Suspend continues Crew before answering so snapshot wake does not wait for resume. Resume continues a stopped Crew and never starts a second one. `/status` reports the sync interval and the last hook outcome.
- **History.** Litestream compacts to a 5-minute level and a 4-hour level, takes a daily snapshot when the database changed and keeps snapshots for 72 hours.
- **Idle guests write nothing.** `drop/idle.py` checks that six idle minutes leave the database, WAL and replica unchanged. The only write after activity stops is Litestream's single checkpoint about a minute later.

Install the release executable and check its SHA-256 against the accompanying checksum file. The app identity, SQLite and attachment storage paths and the replica layout are unchanged; existing replicas continue with the new levels. See the [guest guide](../../drop/README.md#replication-cost-and-loss-window) for configuration and cost behaviour.
